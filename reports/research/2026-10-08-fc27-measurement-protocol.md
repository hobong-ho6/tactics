## P1. First Touch PlayStyle이 볼컨트롤 원값을 얼마나 덮는가 (과녁 1)

### 가설 (반증 가능하게)
- **H1**: 볼컨트롤·침착·차단력이 같은 두 수신자에게 똑같은 강패스를 보내면, First Touch 보유자의 **헤비 터치 비율이 15%p 이상 낮다.**
- **H0**: 차이가 5%p 미만이다 — 그렇다면 FC27에서 First Touch는 원 스탯 대비 **작은 보정**이고, 진화에서 「볼컨트롤 +N」과 바꿀 가치가 낮다.

📌 사전 기대값: EA 게임플레이 총괄 PD가 「PlayStyle 하나의 보너스 목표 = 약 5~10%」라고 밝혔다(`game_system_changes` #50 · A− 인터뷰 · 설계 목표이지 측정값 아님). 설계대로라면 결과는 H0 쪽에 가깝게 나와야 한다 — **그래서 재는 것이다.**

⚠️ 수신 난이도는 **볼컨트롤·차단력·침착 복합 + 상황 변수 6종 + L2/LT 입력**이다(docs/22 §2.1 · A). 그래서 ⑴ 세 속성을 맞춘 쌍을 쓰고 ⑵ 수신자는 **사용자가 조작하지 않는다**(L2 입력 변수 제거).

### 조작 변인 — First Touch 유무 하나

**0단계 — 메뉴 확인(먼저 1분)**: `커스터마이즈 → 팀 편집 → 선수 편집`에서 **PlayStyle을 켜고 끌 수 있는지** 본다.
FC27에서 되는지는 확인되지 않았다(D — 이전 작품 기억에 기댄 추정). 되는 쪽부터 쓰고, 어느 방식으로 했는지 기록란에 적는다.

| 방식 | 내용 | 품질 |
|---|---|---|
| **A** (최우선) | **같은 선수(비르츠)** 의 First Touch만 끄고 켠다. 다른 것은 손대지 않는다 | 완전 통제 |
| **B** | 같은 리버풀에서 **비르츠(FT 있음)** ↔ **알바레스(FT 없음)** 를 같은 CAM 자리에 번갈아 넣는다(선수 이적 메뉴로 알바레스를 리버풀에 임시 이동) | 매칭 쌍 |
| **C** (최후) | 리버풀(비르츠) 블록과 아틀레티코(알바레스) 블록을 따로 한다 — 패서가 달라진다(반 다이크 ↔ 르 노르망) | 패서 변수 남음 → 기록란에 「C」 필수 |

매칭 근거(DB `player_card_items` FC27 base, 2026-10-08):

| 선수 | 볼컨트롤 | 침착 | 차단력 | PlayStyle |
|---|---|---|---|---|
| 비르츠 | 88 | 86 | 55 | Finesse Shot, Chip Shot, Incisive Pass, **Technical**, **First Touch**, Inventive |
| J. 알바레스 | 88 | 86 | 52 | Finesse Shot, Incisive Pass, Press Proven, Low Driven Shot, Dead Ball+ |

⚠️ 방식 B·C에서는 **Technical도 같이 다르다**(비르츠만 보유). Technical이 수신에 관여하는지는 EA 서술이 없다 — 그래서 방식 A가 최우선이다.

### 절차
1. 리버풀(사용자) vs 아틀레티코(AI). 비르츠(또는 알바레스)를 **CAM**에.
2. 공을 잡으면 **센터백 반 다이크**로 전환해 하프라인 근처의 수신자에게 **그라운드 패스, 파워 게이지 최대**로 보낸다. 거리는 대략 **25~35m**.
3. ⛔ 패스 후 **수신자로 전환하지 않는다 / 스틱·L2를 건드리지 않는다**(AI가 트랩한다). 자동 전환이 수신자로 넘어가도 입력하지 않는다.
4. 수신자 **5m 안에 상대가 있으면 그 시도는 버린다**(「상대 압박」 변수 고정). 버린 횟수도 센다.
5. 한 조건 **40회**. 방식 A·B는 **10회씩 번갈아** 간다(FT on 10 → off 10 → on 10 …) — 피로·익숙함이 한쪽에 몰리지 않게.

### 판정 — 한 시도마다 하나
- **클린**: 첫 접촉 뒤 공이 **한 걸음 안**에 머문다.
- **헤비**: 공이 **두 걸음 이상** 튀어 나가 따라가야 한다(상대가 안 와도 헤비).
- **미스**: 공을 놓친다/몸에 맞고 흘러나간다.

### 기록 서식 (그대로 받아적는다)

```text
P1 · 날짜: ____ · 타이틀 버전: v____ · 프리셋: Authentic · 난이도: 월드 클래스 · 방식: A / B / C
| 블록 | 수신자 | FT | 시도 | 클린 | 헤비 | 미스 | 버림(압박) |
|---|---|---|---|---|---|---|---|
| 1 | 비르츠 | on | 10 | | | | |
| 2 | 비르츠/알바레스 | off | 10 | | | | |
| 3 | | on | 10 | | | | |
| 4 | | off | 10 | | | | |
| 5~8 | (반복) | | | | | | |
메모(이상한 장면·패치 알림 등):
```

### 채택 기준
- 헤비+미스 비율이 FT on에서 **15%p 이상 낮음** ⇒ H1 채택 — 「First Touch는 볼컨트롤 원값을 실질적으로 덮는다」(C, n=40×2).
- 차이 **5%p 미만** ⇒ H0 채택 — 「FC27 First Touch 보정은 작다」(C).
- 5~15%p ⇒ **판정 보류**, 40회씩 한 번 더(누적 80×2).
- ⚠️ 두 조건 모두 헤비가 **3회 이하**면 패스가 너무 쉬운 것이다 — 거리를 40m로 늘려 다시 한다.

## P2. 역할을 바꾸면 선수가 실제로 얼마나 움직이는가 (과녁 3 · 가변 과녁 #45 기준선)

### 가설
- **H1**: 오른쪽 풀백의 역할만 **Fullback → Wingback**으로 바꾸면 경기 후 히트맵의 무게중심이 **5×5 격자 기준 1행 이상 전진**한다.
- **H0**: 0.5행 미만 — 「FC27에서 역할 변경의 위치 효과는 작다」.
- 부산물(#45): Fullback 조건 히트맵에서 RB 무게중심이 **센터백보다 뒤(자기 골 쪽)** 로 찍히는 경기가 있으면 「풀백 조기 하강」의 수정 전 기준선이 된다. EA가 고치면 **같은 프로토콜을 그대로 다시** 돌려 전후를 비교한다.

### 통제 조건 (공통 + 아래)
- 아스톤 빌라(사용자) vs 아틀레티코(AI). 포메이션 **4-2-3-1**, 팀 전술은 **프리셋 그대로**(빌드업·수비 접근·라인 높이 모두 기본값 — 값을 기록란에 적는다).
- RB 선수 고정(빌라의 기본 RB). **포커스는 Balanced로 둔다** — 역할만 바꾼다.
  Wingback에 Balanced가 없으면 가장 가까운 포커스를 고르고 기록란에 적는다.
- 사용자는 **평소처럼 경기한다.** 단, RB를 **직접 조작하는 시간을 최소화**한다(수비 시 자동 전환에 맡기지 않고 CB·CDM 위주로 수비) — RB 위치가 사용자 손이 아니라 AI 역할 로직에서 나오게.

### 조작 변인 — RB 역할 하나 (Fullback ↔ Wingback)

### 절차
0. ⚠️ **킥오프 직후 RB가 실제로 오른쪽 풀백 자리에 서 있는지 확인한다.** EA 포럼에 「전술 메뉴와 실제 경기에서 선수 포지션이 바뀐다」는 버그 보고가 있다(D · [forums.ea.com 13743303](https://forums.ea.com/discussions/fc-27-technical-issues-en/player-positions-changing-between-tactics-menu-and-gameplay/13743303)). 바뀌어 있으면 그 경기는 버리고 기록란 메모에 적는다 — 히트맵이 역할이 아니라 버그를 잰다.
1. Fullback(Balanced)으로 **1경기**(하프 6분) → 경기 후 `매치 팩트 → 선수 퍼포먼스 → RB 히트맵` 스크린샷.
2. Wingback(Balanced)으로 **1경기** → 같은 스크린샷.
3. 1~2를 **3쌍**(총 6경기). 순서는 F-W, W-F, F-W로 엇갈린다.
4. 스크린샷은 `reports/ingame/2026-10-xx-protocol-P2/`에 `F1.png · W1.png …` 이름으로 둔다 — 다음 세션이 5×5로 읽는다(불변규칙 8 서식).

### 기록 서식

```text
P2 · 날짜: ____ · 타이틀 버전: v____ · 프리셋: Authentic · 난이도: 월드 클래스
팀 전술 기본값: 빌드업 ____ / 수비 접근 ____ / 라인 높이 ____ / 폭 ____
| 경기 | 역할 | 포커스 | 스코어 | 점유율 | RB 직접 조작 많았나(상/중/하) | 스크린샷 파일 |
|---|---|---|---|---|---|---|
| 1 | Fullback | Balanced | | | | F1.png |
| 2 | Wingback | Balanced | | | | W1.png |
| 3 | Wingback | | | | | W2.png |
| 4 | Fullback | | | | | F2.png |
| 5 | Fullback | | | | | F3.png |
| 6 | Wingback | | | | | W3.png |
메모(RB가 CB 뒤로 내려가 라인을 깨는 장면을 봤으면 시각·횟수):
```

### 채택 기준 (다음 세션이 히트맵을 격자화해서 판정)
- 3쌍 중 **3쌍 모두** Wingback 무게중심이 Fullback보다 앞이고 평균 차이 **≥ 1행** ⇒ H1 채택(C, n=3쌍).
- 평균 차이 **< 0.5행** 이거나 방향이 쌍마다 엇갈림 ⇒ H0 채택.
- 그 사이 ⇒ 보류, 3쌍 추가.
- ⚠️ 점유율이 쌍 안에서 **20%p 이상** 차이 나면 그 쌍은 버린다(공을 오래 가진 쪽 풀백이 원래 더 올라간다).
